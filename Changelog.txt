### 📅 Version History

#### 2026-10-29 — Phase 4 + Phase 6: Desktop Shell, Offline Cache, Panic Cloak & Mirror Routes
*   **Added (Phase 4):** Electron wrapper for the games shell — `electron/main.js`, a secure context-isolated preload bridge, a loopback-only static server, `npm start`, and a portable `release/Pretzel Games-win32-x64/PretzelGames.exe` built by `tools/package-electron.js`. The packaged app ships only runtime files, inside an asar, and loads the same `index.html`.
*   **Added:** Desktop detection in the shell — the diagnostics renderer now reports **Electron shell**, external links open in the system browser, and off-origin navigation is refused.
*   **Added (Phase 6):** Offline fallback through `sw.js`. The shell, fonts, CSS, catalog and config are cached network-first; game frames and third-party requests are never intercepted. Diagnostics shows cache state and Settings can enable or disable the cache.
*   **Added:** Panic cloak overlay bound to `CommandOrControl+Shift+H` — a global shortcut plus an in-page fallback. It covers the window with a blank document, swaps the window title, restores both on the second press, and is reachable from the stage bar.
*   **Added:** `data/mirrors.json` delivery-route manifest with a new Manager **Mirrors** page — primary origin, up to twelve fallback origins, active route, SHA-256 comparison of live `index.html` and `library.json` against the workspace, per-host HTTP status and latency, and **Auto-route** which promotes the first matching host.
*   **Added:** Mirror manifest writes are validated (plain http(s) origins, no credentials/query/hash, no duplicates) and the previous manifest is copied into `.manager/backups/` before the atomic replacement.
*   **Changed:** Every Electron window — shell, Manager dashboard, app test window and frame harness — now opens on the secondary display when one is connected, leaving the primary free.
*   **Fixed:** `data/config.json` was missing the `stealth` block and shipped `offlineFallback: false`, which silently disabled the Phase 6 offline cache despite the code supporting it. Both are now set.
*   **Fixed:** The stealth hotkey registration could leave a dead accelerator registered after a failed rebind; it now restores the previous working shortcut and falls back to the in-page handler.
*   **Verified:** `npm run check` passes for all shell files, `npm run smoke` covers the Electron bridge, service-worker cache, cloak show/hide/title restore, global hotkey registration, 16 tiles and secondary-display placement. The Manager smoke covers six routes and a mirror-manifest save/backup/auto-route roundtrip.

#### 2026-10-29 — Phase 5: Manager.exe Dashboard Delivered
*   **Added:** Standalone Electron management app in `manager/` with its own package, secure preload bridge and five-page control deck (Overview, Catalog, Frame check, Test lab, Files). Built and packaged as `manager/dist/Pretzel Manager-win32-x64/Manager.exe` on Electron 45.1.0.
*   **Added:** Catalog editor for the shared `data/library.json` — create, edit and delete entries, search and platform filter, and save the complete array. The Manager never parses or rewrites application JavaScript.
*   **Added:** Schema v1 validation before any write, timestamped backups in `.manager/backups/`, atomic replacement, and a 40-copy retention cap. Invalid saves are rejected before the backup and the write.
*   **Added:** Frame check page that follows redirects, reports HTTP status and reads `X-Frame-Options` / CSP `frame-ancestors`, plus a visual frame harness with real, simulated-blocked and simulated-crash modes.
*   **Added:** Test lab with all three locked simulations — external-network dropout (local assets stay reachable), forced frame failure states, and 1440 / 860 / 390 layout presets applied to a live app test window.
*   **Added:** Files page with delivery asset inventory, local-reference resolution, workspace paths, manual backup and reveal actions. No deploy packaging panel, per the locked Phase 5 decision.
*   **Added:** Workspace discovery through the saved path, current directory, executable directory and parents, plus a folder picker in the top bar for a portable executable.
*   **Changed:** All Manager windows — dashboard, app test window and frame harness — prefer the widest non-primary display when a second monitor is connected, leaving the primary display clear. Single-display machines fall back to the primary.
*   **Verified:** `npm run smoke` and the packaged `Manager.exe --smoke` cover the preload bridge, five routes, broken-catalog rejection, asset scan, save/backup/reject roundtrip, UI draft/discard, live frame check, blocked-frame harness, app window at 16 tiles, 860/390 resizes and a blocked external fetch while dropout is on. Screenshots land in `manager/.smoke/`.
*   **Note:** The Manager is local-only, unsigned and separate from Phase 4 packaging for the main games shell. Phase 4 remains open.

#### 2026-10-29 — Customization Pass: Settings, Scrolling & Open Roster
*   **Added:** Settings panel (`js/settings.js` + schema-driven renderer) with six sections and 36 rows — accents, density, tile size, glow, motion, chrome toggles, sort control, default filters, AI weights and depth, search engine, home URL, watchdog timing, proxy overrides and log behaviour.
*   **Added:** Settings Export / Import / Reset all, persisting to `localStorage` under `pretzel.settings.v1` and applying live without a reload.
*   **Added:** Browser **Home** button bound to the configurable home destination.
*   **Fixed:** The library grid could stop scrolling — `scroll-behavior: smooth` stalled when animation frames were throttled, and nothing guaranteed the wheel reached the grid. Instant scrolling plus an explicit wheel handler, keyboard scrolling (`↑ ↓ PageUp PageDown Space Home End`) and an edge fade now cover it.
*   **Fixed:** Short windows clipped the game viewport to a strip; the player column scrolls and the frame holds a 320px minimum.
*   **Added:** Universal fighter support in the Debate Matrix — any name resolves to a deterministic scout estimate, labelled SCOUT CARD, so no character is "not on the roster" any more.
*   **Added:** `or` / `against` as matchup separators and "who wins," / "who would win," prefix handling.
*   **Fixed:** A stale cached page could open Settings with an empty body — the panel now re-renders itself when activated while empty, and shows an explicit error card (with a reset action) if `js/settings.js` is missing instead of staying blank.
*   **Added:** Version query strings on the stylesheets and scripts (`?v=4`) so browsers stop mixing a cached script with a newer page.
*   **Added:** Build tag in the stage bar (`v0.1.0-alpha · b4`) that reads the cache key off the loaded `app.js`, so the badge itself proves which build is running; it is mirrored in the boot log and the Settings About row.

#### 2026-10-29 — Phase 3b: Proxy Gateway
*   **Added:** `proxy/vercel/api/proxy.js` + `vercel.json` — free edge-function adapter that strips `X-Frame-Options`/CSP framing headers, drops cookies and encoding headers, injects a `<base>` tag, and exposes a JSON health route.
*   **Added:** `proxy/cloudflare/worker.js` — single-file Worker adapter with the same contract for `npx wrangler deploy`.
*   **Added:** `proxy/README.md` — deployment steps for both hosts, config wiring, security notes and the real limits of document proxying.
*   **Added:** `tools/proxy-dev.js` — local `127.0.0.1:8788` gateway mirroring the contract for testing without deploying.
*   **Added:** `proxy.endpoint` / `proxy.health` / `proxy.token` / `proxy.label` in `data/config.json`, with a `{url}` template placeholder and prefix-append fallback.
*   **Added:** Diagnostics **Test proxy** button and a Proxy node card reporting Unconfigured / Checking / Reachable / Unreachable, probed at boot and on demand.
*   **Added:** `needsProxy` games route through the gateway with a **Proxied** badge in the viewport bar, and show a notice with a direct-load escape hatch when no gateway is configured.
*   **Fixed:** the local dev proxy bound to port 0 when the environment defined `PORT=0`.
*   **Fixed:** retrying the proxy on an already-proxied URL double-wrapped the request; it is now refused with a clear message, and block dialogs show the real host with a `(via proxy)` marker.
